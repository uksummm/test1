# n8n 图片生成工作流批量化改造需求

## 背景

当前有一个原始 n8n 工作流 JSON：

`细节保真图片优先-V5.1-工作流3-图片生成.json`

这个原始工作流目前可以稳定执行单条表格行的图片生成任务。

当前逻辑大致是：

1. 读取 Google Sheets 中图片状态 = 待生成图片 的第一条记录
2. 解析参数
3. 按“每次生成数量”拆分为多张图片任务
4. 逐张调用 OpenRouter 生图
5. 上传 Google Drive
6. 聚合图片链接
7. 回填 Google Sheets

当前问题：

1. 读取节点只筛选：图片状态 = 待生成图片
2. 读取节点设置了 returnFirstMatch = true
3. 每次只能执行 1 条
4. 我希望自动执行全部符合条件的行

## 改造目标

只做两个目标。

### 目标 1：增加筛选条件

只有同时满足以下两个条件的 Google Sheets 行，才可以进入图片生成流程：

- 提示词状态 = 提示词已生成
- 图片状态 = 待生成图片

### 目标 2：实现批量自动执行

我希望工作流可以自动处理全部符合条件的行。

但是注意：

不要把多行数据一次性塞进原来的生图链路。

原因：

原工作流很多 Code 节点使用：

- `$input.first().json`
- `$('某节点').first().json`

所以这套结构本质适合“单行任务”。

正确方式是拆成两个工作流。

---

# 需要输出两个 n8n workflow JSON

## 工作流 A：单条图片生成器

基于原始工作流改造。

它只负责每次处理 1 条符合条件的表格行。

要求：

1. 「读取待生成行」节点增加双条件：
   - 提示词状态 = 提示词已生成
   - 图片状态 = 待生成图片

2. 保持：
   - returnFirstMatch = true

3. 「筛选待生成」节点也增加双条件兜底：
   - 提示词状态 = 提示词已生成
   - 图片状态 = 待生成图片

4. 建议在读取到目标行后，先把该行的“图片状态”更新为“生成中”，防止重复读取。

5. 保留原来的核心生图逻辑：
   - 解析参数
   - 按数量拆分任务
   - 下载产品图转 base64
   - 组装 OpenRouter 请求
   - 调用 OpenRouter
   - 解析返回图片
   - 上传 Google Drive
   - 聚合链接
   - 回填成功/失败状态

6. 不要删除或弱化“每次生成数量”。

7. 如果某一行“每次生成数量 = 4”，工作流 A 应该生成 4 张图，并把 4 个 Drive 链接聚合回填到该行。

8. 不要重写 prompt。

9. 不要重写 OpenRouter 请求体。

10. 不要重构整个工作流，只做必要改造。

输出文件名：

`01_单条图片生成器.json`

---

## 工作流 B：批量循环控制器

新建一个简单调度工作流。

它不负责生图，只负责循环调用工作流 A。

逻辑：

1. 手动触发
2. 读取 Google Sheets 中所有符合条件的行：
   - 提示词状态 = 提示词已生成
   - 图片状态 = 待生成图片
3. 统计符合条件的行数 count
4. 循环 count 次
5. 每次循环调用一次工作流 A
6. 每次调用后 Wait 10-30 秒，避免 OpenRouter / Google Drive 请求太密
7. 直到全部符合条件的行处理完毕

注意：

工作流 B 不要把多行数据传进工作流 A。
工作流 B 只需要重复调用工作流 A。
每次由工作流 A 自己重新读取当前第一条符合条件的行。

输出文件名：

`02_批量循环控制器.json`

---

# 验收标准

## 测试 1：筛选条件

只有同时满足以下条件的行会被处理：

- 提示词状态 = 提示词已生成
- 图片状态 = 待生成图片

## 测试 2：单条多图

如果某一行：

- 每次生成数量 = 4

执行工作流 A 后，应生成 4 张图，并把 4 个 Drive 链接回填到该行。

## 测试 3：批量执行

如果表格里有 5 行符合条件，执行工作流 B 后，应该依次调用工作流 A 5 次，每次处理 1 行，直到全部完成。

不能出现：

1. 第一条成功，后面全部失败
2. 有生成链接但图片状态被写成生成失败
3. 多行数据一起进入原来的 Code 节点导致 `$input.first()` 串数据
4. 删除“每次生成数量”
5. 重写核心生图 prompt
6. 重写 OpenRouter 请求体

请优先保证稳定，不要过度优化。
